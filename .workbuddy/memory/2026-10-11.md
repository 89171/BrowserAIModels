### 修复的 3 个缺陷
1. **ORT 后端加载失败（真机才暴露）**：`scripts/copy-ort-wasm.cjs` 原来只拷 `jsep` + 普通两套，运行时 ORT 会去请求
   `ort-wasm-simd-threaded.asyncify.mjs` → `no available backend found`。改为用 `readdirSync` 过滤
   `/^ort-wasm-.*\.(mjs|wasm)$/` 全量拷贝（8 个文件 / 82.5 MB，`public/ort/` 已在 .gitignore）。
2. **「演示模式」被误标为「真实计算」**：`lib/engine/index.ts` 里 `simulated = real ? false : isSimulated(...)`，
   而 `isSimulated` 对 `labels` 恒返回 false。改为 `simulated = !real`，另用 `simulatorOnly` 区分
   「纯随机模拟」与「像素/频谱/向量真算但权重是模拟」的说明文案。
3. **缓存/空结果文案误导**：
   - 从 Cache Storage 读取时 ORT 仍报进度，故 `↓ 64.2 MB` 改为中性文案 `权重 64.2 MB`（新增 `weightsMovedHint`）。
   - `loadPipeline` 命中内存缓存时返回 `bytes: 0` → 显示 `权重已缓存`。
   - 检测零结果原显示「尚未运行」，新增 i18n `noDetection` 提示降低阈值或换图。
   - 冷启动进度条的 `100%（0.7 MB）` 抖动：total ≤ 1 MB 的小文件不再显示百分比。

## 全量巡检（30 子类 × 103 模型）—— 全通过
做法：写一个页面内巡检脚本，遍历某子类「切换模型」区的每个按钮 → 点运行 → 等按钮文案回到空闲态 →
抓取输出区抬头、badge、是否有空态/失败态、控制台 error/warn，再汇总。
**脚本选择器的三个坑（都踩过）：**
1. `agent-browser eval` 注入中文脚本必须 `eval(decodeURIComponent(escape(atob(b64))))`，
   直接 `atob` 拿到 latin1，中文正则全部失效。
2. 不能靠按钮上的 `MB` 定位模型按钮 —— 部分模型 size 是 `runtime` / `~80 KB`。
   可靠特征：切换区按钮里有分隔 framework 与 size 的 `<span>·</span>`，底部「全部模型」列表没有。
3. 排除运行按钮别用 `/Run/` —— 会误伤 `ONNX Runtime Web` 的模型按钮。
结果：模型名与输出抬头一致 103/103、选中态 103/103、输出非空 103/103、无超时、无控制台报错。
badge 真实权重 8 个（= REAL_MODELS 登记数），演示模式 95 个。
图片类输出另做抽查（img complete 且 naturalWidth>0）：depth 640x480、segmentation 480x640、文生图 640x640、视频 6 帧缩略图，均正常。

## 「切换模型看不到下载」—— 定位与 UI 修正
用户反馈切换模型看不到下载过程。真机录制（20ms 采样 `.pulse` 文案）确认三种情形，均属预期：
1. 切到**首次访问的真实权重模型** → 完整下载：`准备权重…` → `下载权重 N%（N MB）` 递增至 100%。
   Toxic-BERT 105.1 MB / 33.1 s，DistilBERT 64.2 MB / 19.1 s，两者字节曲线完全不同 → 确系换仓库。
2. 切到**已加载过的真实权重模型** → 266 ms，无下载，结果显示「权重已缓存」。
3. 切到**无浏览器权重的模型（95/103 = 92.2%）** → 120 ms，永不下载。
**根因是 UI 没把「哪些会下载」说清楚，且有一处撒谎**，已修：
- `lib/engine/index.ts` 模拟分支 phase 原为「加载权重…」→ 改为「演示模式：不下载权重，用模拟引擎计算…」。
  这是最大的误导源：模拟模型也喊「加载权重」，用户自然以为权重没下下来。
- `DemoPlayground` 模型按钮徽章：有真实权重 → 实线 pill `◆ 浏览器权重`（9.5px / opacity 0.9~1，原来 9px/0.65 几乎看不见）；
  无权重 → 虚线 pill `模拟`（并 hover 提示原因）。此前无权重模型**完全没有标记**。
- 切换区标题追加「· 其中 N 个有真实浏览器权重」；底部模型列表给有权重的加 `◆`。
- 右侧 notes 按 `realCount` 分叉：有 → 解释首次下载/之后走缓存；无 → 明说「本子类下所有模型都没有…不会触发任何下载」。
- 坑：`border-dashed` class 被 `globals.css` 的 `* { border-style: solid }` 覆盖（该全局规则为 Tailwind v4 preflight 补边框色所加），
  虚线必须写成 `style={{ borderStyle: 'dashed' }}` 内联。
验证：tsc ✅ / eslint ✅ / build ✅ / 30 页 HTTP 200 ✅ / 截图确认徽章渲染 ✅。

## 「模拟」标记的语义分层（用户追问它到底算不算真实调用）
「模拟」不是一个意思，代码里其实是三层，此前按钮上混成一个词，已让它可解释：
1. **真实模型推理**：8 个模型，跑 ONNX 权重（`real.ts`），badge「真实计算」。
2. **真实信号处理 + 模拟权重** (`simulatorOnly=false`)：Canvas 像素（depth/segmentation/restoration/inpainting/generated-image）、
   STFT 频谱（audio-compare/stems/denoise）、向量检索（embedding/ranking/search）、波形合成（synth-audio/music）、关键点（landmarks）。
   结果确实从输入算出来，但**不来自那个模型**。
3. **纯确定性模拟** (`simulatorOnly=true`)：text/chat/json/code 等，种子驱动，同输入恒同输出。
实现：抽出 `export const computesRealSignal(kind)`（`lib/engine/index.ts`，`REAL_SIGNAL_KINDS` 集合），
`isSimulated()` 复用它；UI 用它决定 tooltip 二选一（`simulatorSignalHint` / `simulatorRandomHint`）。
坑：`DemoPayload['kind']` 用 `'landmarks'`，而 `OutputKind` 用 `'landmarks-face'/'pose'/'hand'` —— 集合要同时收，
签名写成 `OutputKind | DemoPayload['kind']`。

## 真实权重扩展（覆盖 3 → 10 个子类，15 个模型）
用户要求"所有子类都跑真实权重"。**物理上不可行**：30 个子类里约 13 个没有浏览器可加载的 ONNX 权重。
盘点方法：HF API `GET /api/models/{repo}` 判仓库存在（**401 = 不存在**，200 = 存在），
再用 `HEAD https://huggingface.co/{repo}/resolve/main/{file}` 确认权重文件真实可下载并读出 content-length。
⚠️ 坑：批量探测时多个不同仓库会返回"看起来相同"的 siblings 头部（`.gitattributes/README.md/config.json`），
不能据此判断；必须用 resolve/HEAD 逐个确权文件 + 体积。

**权威可行性来源**：`node_modules/@huggingface/transformers/src/pipelines/` 目录（该库只实现了这些 task）：
automatic-speech-recognition, depth-estimation, document-question-answering, feature-extraction,
image-classification, image-feature-extraction, image-segmentation, image-to-image, image-to-text,
object-detection, summarization, text-classification, text-generation, text-to-audio, text2text-generation,
token-classification, question-answering, fill-mask, background-removal, audio-classification。

已接入的task → 仓库（dtype / 体积）：
- asr→Xenova/whisper-tiny q8 29MB | tts→Xenova/mms-tts-eng q8 37MB（Silero 替身）
- ocr→Xenova/trocr-small-printed q8 39MB（PaddleOCR 替身，整图单行无框）
- image-restoration→Xenova/swin2sr-classical-sr-x2-64 q4 22MB（SwinIR 替身）
- summarization→Xenova/distilbart-cnn-6-6 int8 147MB（Pegasus 替身）
- depth→Xenova/dpt-hybrid-midas q4 182MB | vlm→Xenova/vit-gpt2-image-captioning q8 151MB（Moondream2 替身）
**未做**：multimodal/clip（需加载 text+vision 双塔，体积翻倍，已在 real-models.ts 留 roadmap 注释）；
llm/* 三个子类（Qwen1.5-0.5B q4 460MB / codegen-350M 346MB / TinyLlama 1GB，浏览器体验过差）。
**物理不可行**：text-to-image、inpainting（SD 需 UNet+VAE+TextEncoder，数 GB）、denoising、source-separation、
text-to-music、real-time/{face,hand,tracking,pose}（无对应 pipeline）、video-understanding。

实现要点：
- `real.ts` 新增 transcribeAudio / synthesiseSpeech / captionImage / summariseText / enhanceImage / estimateDepth。
- RawImage 序列化跨版本不稳，写 `toDataUrl()` 依次尝试 `toDataURL()` → `toCanvas().toDataURL()`。
- TTS 需要把 Float32 PCM 编成 16bit WAV Blob URL 才能播放（`pcmToWavUrl`），另用 `waveformPeaks()` 降采样给波形图。
- **踩到的真 bug**：Whisper 不传 language 时按英文解码，中文示例被转成英文（告警 `No language specified`）。
  加 `LoadOptions.language`，由 `isChineseSample(ctx)` 从 sampleId/locale 推断 zh|en。
- Whisper 在浏览器走 **WASM 而非 WebGPU**（WebGPU 会话创建失败后静默回退），7 秒音频约需数分钟，体感很差。
实测分级正确：classification/chat → 纯随机文案；depth/embedding/tts → 真信号处理文案。
